# Gemini 3.0 Flash Preview STT アプリケーション プロジェクト概要

## 1. プロジェクト基本情報
*   **アプリケーション名**: Gemini AI Speech-to-Text (STT)
*   **ドメイン**: stt-gemini.minashin1120.com
*   **目的**: ブラウザ上での直接録音、またはユーザーがアップロードした音声ファイルを、Google Gemini 3.0 Flash Preview モデルの推論能力（Thinking Process）を用いて高精度に文字起こしする。
*   **主な機能**:
    *   **ハイブリッド音声入力**: ブラウザ上でのリアルタイム録音（MP3/WAV, ノイズ除去対応）と、音声ファイルのアップロード（ドラッグ＆ドロップ対応）の両方に対応。
    *   リアルタイム文字起こしと推論プロセスのストリーミング表示.
    *   AIへの指示によるテキストの修正・改善.
    *   音声ファイルのサーバー保持（ユーザー設定による、デフォルト10分間）と再分析・削除・再生機能.
    *   **単語リスト管理**: 特定の読み方を検知した際に、指定した単語（専門用語や固有名詞など）に置換するカスタムボキャブラリ機能。
    *   **セット管理**: 複数の単語を「セット」としてまとめ、必要に応じてオン/オフを切り替え可能。
    *   デザインテーマ切り替え（ゲーミング、レトロ、モダンなど）。

    *   履歴とデータの保持時間をユーザー設定から変更可能（5分〜1440分）.
    *   操作履歴の保存とコンテキスト連携.
    *   手動セッションリセット機能（履歴の即時クリア）.

## 2. インフラ・環境構成
*   **OS**: Debian 12 (Linux)
*   **Webサーバー**: Apache 2.4 (Reverse Proxy / SSL)
*   **アプリケーションサーバー**: Gunicorn (Python WSGI HTTP Server)
*   **データベース**: MariaDB 10.11
*   **SSL**: Let's Encrypt (Certbot)
*   **ポート構成**:
    *   **Public**: 443 (HTTPS), 80 (HTTP) -> Apacheが受ける
    *   **Internal**: 8003 (Gunicorn/Flask) -> Apacheから転送

## 3. ソフトウェアスタック
### バックエンド
*   **言語**: Python 3.11 (venv環境)
*   **フレームワーク**: Flask 3.0.0
*   **ORM**: SQLAlchemy 2.0 (Flask-SQLAlchemy)
*   **認証**: Flask-Login
*   **API通信**: `requests` ライブラリを使用（SDKのバージョン問題回避のため、Gemini REST APIを直接コール）
*   **暗号化**: `cryptography` (APIキーの保存用)

### フロントエンド
*   **言語**: HTML5, JavaScript (Vanilla ES6+)
*   **デザイン**: Bootstrap 5.3, Bootstrap Icons
*   **通信**: Fetch API, Server-Sent Events (SSE)

## 5. データベース構造 (MariaDB)
データベース名: `stt_gemini_db`

### User テーブル
ユーザー認証と設定を管理します。
| カラム名 | 型 | 説明 |
| :--- | :--- | :--- |
| `id` | Integer (PK) | ユーザーID |
| `username` | String(150) | ログインID (Unique) |
| `password` | String(255) | ハッシュ化されたパスワード |
| `encrypted_api_key` | Text | 暗号化されたGemini APIキー |
| `retention_minutes` | Integer | 履歴・データの保持時間 (分) |

### History テーブル
過去の操作履歴を保存し、コンテキストとしてモデルに渡すために使用します。
| カラム名 | 型 | 説明 |
| :--- | :--- | :--- |
| `id` | Integer (PK) | 履歴ID |
| `user_id` | Integer (FK) | ユーザーID |
| `action_type` | String(50) | 操作種別 (`transcribe`, `improve`, `reanalyze`) |
| `input_summary` | Text | 入力内容や指示 |
| `thought_text` | Text | モデルが出力した推論プロセス |
| `result_text` | Text | 最終的なテキスト結果 |
| `timestamp` | DateTime | 実行日時 (UTC) |

### WordSet テーブル
ユーザー別のカスタム単語セットを管理します。
| カラム名 | 型 | 説明 |
| :--- | :--- | :--- |
| `id` | Integer (PK) | セットID |
| `user_id` | Integer (FK) | ユーザーID |
| `name` | String(100) | セット名 |
| `is_active` | Boolean | 有効フラグ |

### Word テーブル
セットに含まれる具体的な単語とその読み方を管理します。
| カラム名 | 型 | 説明 |
| :--- | :--- | :--- |
| `id` | Integer (PK) | 単語ID |
| `set_id` | Integer (FK) | セットID |
| `reading` | String(255) | 読み（検知対象） |
| `replacement` | String(255) | 置換後の単語 |

## 6. 実装済み機能の詳細

1.  **Thinking Process (推論) の分離**:
    *   Gemini 3.0 Flash Previewの仕様に基づき、REST APIのレスポンスから `thought` フィールドと `text` フィールドを分離し、SSEでストリーミング配信。
    *   フロントエンドではアコーディオンUI内に推論を表示し、最終結果と区別。
2.  **ハルシネーション対策**:
    *   システムプロンプトにて `VERBATIM_INSTRUCTION` (一字一句正確に、事実を勝手に修正しない) を定義し、モデルによる勝手な日付変更などを抑制。
3.  **音声ファイル・履歴管理**:
    *   アップロードされたファイルおよび履歴は、ユーザーが設定した「保持時間」を過ぎるとバックグラウンドスレッドによって自動削除される。
    *   デフォルトは10分で、設定画面から変更可能。
    *   ユーザーは期間内であれば「再分析（Re-analyze）」や手動削除が可能。
4.  **UI/UX**:
    *   **ゲーミングモード**: RGBウェーブアニメーション（背景・枠線など）.
    *   **設定保存**: Cookie/LocalStorageを使用し、テーマやThinking Levelの設定を保持。
    *   **トースト通知**: 操作結果を画面右上にポップアップ表示。
    *   **セッション**: 31日間のログイン保持。

11. **機能改善 (2026-02-23)**: 
    *   **個別削除機能の実装**: 保存データ（ファイル）および履歴を、リストから一つずつ個別に削除できる機能を追加。

    12. **機能追加 (2026-02-23)**: 
        *   **データ保持時間の設定機能**: ユーザーが設定画面から履歴とデータの保持時間（分）を変更できるようにした。

        *   **コンテキストへの反映**: Geminiへのプロンプト構築時に使用する履歴の有効期限も、ユーザー設定値を参照するように修正。

        *   **録音の安定性向上**: `ScriptProcessorNode` のバッファサイズ調整とクリッピング防止処理を追加し、より生の状態に近い高品質な録音を可能にした。

    16. **バグ修正 (2026-03-27)**:

        *   **手動修正の完全反映**: 
            *   **データベース同期**: 「改善」実行時に、テキストエリアの手動修正内容をサーバー側の最新履歴に即座に反映するようにし、Geminiが参照する履歴コンテキストを最新の状態に同期。
            *   **プロンプト強化**: Geminiに対し、「Current Text（手動修正後のテキスト）」を最優先のソースとして扱うよう明示的に指示し、モデルが古い文字起こし結果に引きずられる問題を解消。
            *   これらにより、ユーザーの修正意図が確実に改善結果に反映されるように挙動を安定化。

## 8. 開発環境のセットアップと実行
ローカルで開発サーバーを起動する手順は以下の通りです。

1.  **前提条件**:
    *   `app/.env` ファイルに記載されている接続情報でアクセス可能なMariaDBサーバーが起動していること。
    *   Python 3.11 がインストールされていること。

2.  **セットアップ**:
    ```bash
    # 1. アプリケーションディレクトリへ移動
    cd app

    # 2. Python仮想環境を有効化
    source venv/bin/activate

    # 3. 必要なライブラリをインストール
    pip install -r requirements.txt
    ```

3.  **実行**:
    ```bash
    # 4. Flask開発サーバーを起動
    #    初回起動時にデータベーステーブルが自動的に作成されます。
    python app.py
    ```
    サーバーは `http://localhost:8003` で起動します。
